# P03-01 — Preliminary client intake

Implementation increment for the existing Control plane, not a complete onboarding flow. See the authoritative [FDV roadmap](https://github.com/NIXINX-Business-Transformation/nixinx-dwh/blob/main/docs/implementation/NIXINX_PROVISIONING_MASTER_ROADMAP.md).

Superadmin-only UI in Clientes and server endpoint. Production-only creation of a preliminary server-side record in clientProvisioning keyed by canonical tenant ID, with exact replay and independent readback. No writes to tenants, apps, configurations, appInstallations, licenses or providers; no secrets, invitations, resource creation, or entitlement. Legal identity and consent are not attested by form entry. Existing tenants and conflicts stop for reconciliation, not duplicate creation. The existing catalog lacks a verified legal-identity registry; legal-key comparison only detects normalized exact duplicates among preliminary records. Current scans stop above 500 records; indexing, multi-product incremental onboarding, edits with audited revisions, delegation, durable provider operations and runtime authorization are subsequent P03/P04/P05 gates. No customer data in GitHub. UI only exposes preliminary records to authenticated superadmins. Test real persistence and idempotency using an explicitly authorized client before certification.
