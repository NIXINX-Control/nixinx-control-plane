# P03-02M — Delegated metadata discovery

Existing active tenant intake only. Explicit superadmin owner-authorization attestation and immutable binding saved transactionally with existing firebaseProjectOwners registry; reservation does not publish runtime config. Corporate/client pool targets and dedicated SA derived from stored binding; no arbitrary token, URL, principal or target supplied to discovery. STS followed by IAM Credentials generateAccessToken (600s) and existing metadata adapter. No document/user access or SDK config retrieval. Result persisted with audit/readback; no technical or commercial activation. Historical metadata is not proof of current access; each discovery requests a new short-lived credential. No automatic mode fallback. No production auth or Preview changes. Live HTL check, inherited permissions, negative segregation and revocation checks remain gates. Binding edit/revocation lifecycle and new-customer flow not implemented.
